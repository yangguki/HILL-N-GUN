## Root cause (slice C APK: only 2D shows)

Two issues stacked, both consistent with “2D only” on a device:

1. **The 3D presenter factory was not a linker root.** `Proto_Greybox3DViewBootstrap` lived only as an unreferenced static class with `[RuntimeInitializeOnLoadMethod(AfterAssembliesLoaded)]`. Greybox does not compile-time reference Greybox3D; the Resources Catalog can pull the assembly into the player, but Low IL2CPP stripping can still drop an unused bootstrap type. If the factory never registers, `ViewPresenterRegistry.Ensure()` returns null, `SetActive` is skipped, and the default view stays 2D. The editor (full assemblies, no IL2CPP strip) still switched fine, which is why screenshots and EditMode looked OK.
2. **The only switch was the DBG “View: 2D / 3D” row** (F1 or a small on-screen DBG button). Even with a working factory, that control is easy to miss or hard to hit on a phone, so a first launch (prefs default 2D) would only ever show 2D.

Also hardened while diagnosing:

- `ApplyViewMode` hid 2D *before* `SetActive`. If 3D was requested but the presenter was null or creation threw, you could get a blank HUD. Failures now revert to 2D, keep the 2D camera on, and show the error text on a HUD banner (Greybox-side, so it still appears if Greybox3D types never loaded). Prefs are not wiped, so the user can retry.
- `Find2DWorldCamera` used `StageBuilder.GetComponentInChildren<Camera>`. After a 3D switch the ViewRoot is parented under the stage, so that lookup could return the **3D** camera and then disable it on a later apply. It now only returns a camera with `Proto_GreyboxCameraSetup`.

Shaders, FBX, and animation clips were already referenced on `Resources/HillNGunGreybox3D/Catalog` from slice C; Catalog tests now also assert the cowboy model and Idle/Walk/Shoot clips are present.

### Fix

- `Proto_Greybox3DViewBootstrap.Register()` is public, `[Preserve]`, and hooked from both `SubsystemRegistration` and `BeforeSceneLoad`.
- The Resources-referenced `Proto_Greybox3DCatalog` static constructor also calls `Register()`, so a type that is definitely in the player keeps the factory alive.
- `Assets/HillNGun/Proto/Greybox3D/link.xml` preserves the whole `HillNGun.Proto.Greybox3D` assembly.
- Player-facing **2D / 3D** buttons in the pause menu (large purple/blue button under the title) and the 설정 / SETTINGS panel (above 닫기 / CLOSE). Hit-tested through `GatherPointers` like Resume/Settings; labels read `View: 2D` or `View: 3D`. DBG toggle still works.
- If 3D creation throws or the factory is missing, a red on-screen banner shows the error and the game stays in 2D.

## How to switch (player-facing)

Default launch is still **2D**.

1. Pause (top-right pause icon) → tap the large **2D / 3D** button under the title → Resume.
2. Or Pause → 설정 / SETTINGS → the same **2D / 3D** button above 닫기 / CLOSE.
3. DBG **View: 2D / 3D** still works (F1 / DBG button).

The choice is saved in PlayerPrefs `HillNGun.Greybox.ViewMode`. A later launch applies 3D on startup when that pref is 3D (and now actually creates the 3D stage).
