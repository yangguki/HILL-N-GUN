## Bug root cause (slice B APK: screen shows, nothing works)

Confirmed on both the default **2D** path and the **3D** path, because 2D startup still built the 3D stage.

1. Custom shaders `HillNGun/Proto/Greybox3D/{Cel,Glow,BlobShadow,Sky}` were created only through `Shader.Find` in `Proto_Greybox3DMaterials`. They were **not** referenced by any scene, Resources material, or Always Included list (`GraphicsSettings` has only built-ins). Unity player/IL2CPP therefore **stripped** them from the Android APK. `Shader.Find` returns null on device (it still works in the editor, which is why screenshots and EditMode were fine).
2. `EnsureLogic()` / `ApplyViewMode()` always called `ViewPresenterRegistry.Ensure()`, which **eagerly** ran `EnsureCreated()` and built the full 3D town + cowboy even when the default view was 2D. `new Material(null)` (or the first 3D setup step after a missing shader) **threw in `Awake`**, killing the player controller. The HUD/stage still rendered, but `Update` / `GatherPointers` never ran, so sticks and buttons did nothing.
3. Other suspects were checked and are not the primary cause:
   - `Time.timeScale` in repo `TimeManager` is 1; pause only sets 0 when the user opens pause.
   - Combat input uses custom `GatherPointers` (`Input.touchCount` / mouse), not uGUI raycasts. The settings `EventSystem` + `GraphicRaycaster` on the HUD predated slice B and would not by itself freeze the whole loop. The fault banner added in this slice has `raycastTarget = false`.
   - No Android device/`adb` was attached here, so this was reproduced from the build graph + editor load path, then guarded in code.

### Fix

- Reference the four custom shaders on `Resources/HillNGunGreybox3D/Catalog` so they are included in the player build. Materials bind from the catalog first; `Material` construction is null-safe.
- `Registry.Ensure()` no longer builds the 3D stage. The stage is created only when 3D is activated (`SetActive(true)`). A 2D launch can no longer be taken down by a 3D asset/shader failure.
- Presenter `SetActive` / `Sync` / `EnsureCreated` are try/caught. Failures go to a DBG “3D FAULT” line and a non-blocking HUD banner (`Proto_Greybox3DFault`). `ApplyViewMode` also catches presenter exceptions.

## Design changes (closer to the concept)

- **Town:** 3 storefronts per side flanking the street + a 3-building back row (porch posts, awning, sign board, plank hints). Fewer polys than the old 7-wide wall.
- **Hero / grunt:** Wide-brim purple (hero) / brown (grunt) hat with a red band; dark brown hair so the back of the head is not a bald oval; belt + holster; hero revolver; chibi scale. Grunt min height raised to 2.9 so they read past the fence.
- **Look:** Solid warm orange sand (the pack dirt tex is labeled “Dirt SandStone” and was not used) plus color patches and tufts; deeper blue sky, puff cloud cards, mesas; cel saturation 1.55; world-space outlines kept.
- **Camera:** Closer / lower — large hero at the bottom-center, fence mid-screen, enemy row and town above, sky band on top.
- **Bullets:** Enemy capsules bigger (0.55 × 1.15) with a glow shell and TrailRenderer; ally tracers smaller yellow.
